# 随机场景与同进程连续运行

复用 `fishbot_simulation_suite.py` 的启动门禁、Goal 客户端、真值采集和报告。新入口只组合场景与运行时间，不新增导航或任务调度框架。模型与实际物理步进仍由既有 MuJoCo 栈提供。

## 随机场景

首次运行修复版前，构建项目本地的生命周期管理器补丁：

```bash
./tools/fishbot_nav2_state_query_overlay.sh build
```

只构建官方Nav2 1.3.13的 `nav2_lifecycle_manager`；源码、编译产物与校验回执保存在本机缓存，不替换系统安装。campaign入口校验产物后选择该前缀。缺失或改动的产物明确报错，不静默回退。补丁范围、许可与真实服务验收见 [补丁说明](../tools/patches/README.md)。

在本项目根执行：

```bash
./fishbot.sh sim-campaign --mode random --seed 1200 --count 20
```

使用独立 domain102。每个场景记录自己的种子与实际参数：门宽36–46厘米，初始朝向±0.25弧度，终点x为1.20–1.40米、y为±0.10米。每四个场景之一在真值确认移动后断开扫描0.65–1.00秒，再转发新收到的原始时间戳扫描。

随机输入可重放；生成参数不表示该范围全部可通行。失败计入分母，原始日志、参数和动作结果保留。沿用既有启动恢复：只有明确未发送命令、已清理、真值静止的就绪超时可重启一次。动作发送或接受结果未知时禁止重发。

## 连续运行

在本项目根执行：

```bash
./fishbot.sh sim-campaign --mode soak --soak-seconds 1800
```

使用独立 domain96。只启动一次门宽40厘米的导航栈与真值记录器。连续提交前进、返程目标，逐个确认真实动作终态与停车反馈。机器人需要掉头；`PoseProgressChecker` 同时识别平移和转角进展，半径4厘米、转角0.1弧度、无进展超时20秒。原地转动不再被只看平移的检查误判，但碰撞监测、源新鲜性和超时仍有效。

修复版复用一个常驻 `PassageGoalRuntime`、Node和ActionClient，全部往返共用；目标之间继续spin，不再每个目标新建Python进程和DDS参与者。每个目标仍只发送一次。未知接受、结果异常、未停稳或清理失败保留原PendingGoal并禁止下一目标。尝试在发送前计入分母，实际接受后的终态单独计数。

记录器只在新真值出现时原子更新 `latest-truth.json`，就绪后停止启动阶段的生命周期查询。checkpoint先读取帧，再独立记录当前steady和ROS时间；源龄期不借用最后一帧保存的时钟。长测资格同时检查整个就绪区间及每个Goal，目标之间的静止空窗也按原300毫秒门限评分。

本入口复用既有 `tolerant` 守卫：普通时序故障零速暂停，健康持续0.2秒后只接受恢复边界以后的新命令；硬故障仍锁存。该档的odom和命令年龄门限为0.35秒，严格档为0.25秒。独立真值评分仍使用0.25秒双龄期及0.30秒最大间隔，没有放宽。无停顿的长测不能证明暂停恢复；实际运动断流恢复由随机 `scan_gap` 案例单独验收。

定位使用现有 AMCL，独占 `map → odom`，就绪门禁验证其实际 ACTIVE 状态。静态fixture变换只保留在原固定suite和随机场景中，不参与本入口的长测。AMCL参数复用短往返已验收的窄sigma与180束扫描；最终到点仍由独立MuJoCo真值核对。

运行时每10秒采样本轮launch进程组的RSS、文件描述符数及PID。不会检查其他任务的进程，也不重启失败任务。最终报告给出每个往返Goal的独立轨迹、停顿和物理终点误差。

使用 `--soak-seconds 60` 可做短验收。短验收成功不能满足30分钟验收。`soak.qualified_30_minutes` 只有同时满足持续时间≥1800秒、同一launch、至少两次收束、全部Goal通过及正常清理时才为true。

## 证据与边界

默认报告位于 `~/.cache/fishbot/simulation-campaigns/`。可使用 `--output` 指定一个尚不存在、位于源码仓库外的目录。产物包括报告、源码SHA、参数、实际动作结果、连续真值、逐Goal真值片段、资源样本和启动日志。

逐Goal评分使用独立记录器当时观察到的时钟及本机单调时间。禁止把最后一帧源时间戳当成当前时间。真值缺失、源时间不推进、接收超限或最终没停稳都不能判通过。

本轮campaign保留11个运行源码的启动SHA。AMCL生成参数文件保留全文，但没有启动前生成参数SHA；`parameter-readback-after-start.json`只记录运行中后验读取及按当前输入逐字节重建的结果，不能证明启动前或全程参数未变。该边界不改变已记录的物理动作评分。后续由root在节点启动前补参数来源与生成文件SHA，不事后补造本轮启动回执。

本入口不操作实车、无线网络、固件或旧domain93网页。实验覆盖的是所列合成场景与运行时长；不能由此推断真实无线稳定性、真实传感器准确率或生产可靠性。

## 本轮结果

2026-10-12 短往返a：去程通过，返程在持续转向时被 `SimpleProgressChecker` 判为无进展，动作终态6。改用安装的Nav2 1.3.13官方 `PoseProgressChecker` 后，b两动作成功，但返程真值误差19.25厘米，仍失败。c接入AMCL后2/2通过，去程误差0.30厘米，返程2.74厘米，实际耗时117.8秒。失败a/b完整保留。

首次30分钟尝试 `soak-20261012-final-a` 在989.182秒停止：13个Goal通过，第14个客户端未发送Goal。严格守卫在静止时因odom接收年龄0.347603秒锁存；独立采集器就绪后有效观测段最大接收间隔0.105361秒、源间隔0.090秒。完整采集包含启动，最大接收间隔0.348660秒、源间隔0.350秒，不把启动空窗排除后称为全程连续。Guard自己的odom、scan和clock在触发窗口滞后，现有证据不能进一步区分局部调度、DDS或同步查询；不能归因于网络或触发文件写盘。此轮没有达到30分钟，评分13/14失败批次。

原执行报告保存为 `execution-report.json`。记账修复后按原连续记录离线重算：守卫事件只关联所属Goal窗口，失败时长如实保留，原执行和分析SHA分别记录。后续新的完整长测采用上述既有暂停恢复模式，结果单独记录。

随机批次 `random-20261012-final-a` 完成20个种子1200–1219，首次通过19/20，无自动重启。19个实际Goal均返回终态4，独立真值终点误差2.42–3.45厘米，最终停稳。4个运动断流案例实际断流0.822–1.084秒，均由同一Goal暂停后恢复，无人工解锁。

种子1207在55秒启动门禁超时，未启动Goal客户端。静止记录出现0.381秒接收间隔、0.370秒源间隔，不满足原有0.300秒连续性要求，因此没有自动重试；它保留在20例分母中。批次整体为failed，不能写成20/20。root按原始记录独立重算20例检查并核对清理完成。

随机批次启动时的campaign全文归档为 `execution-source-campaign.py`，SHA以 `report.json` 为准。运行中只修订了 `run_soak` 的真实终态计数；随机父进程已加载原代码，其执行哈希保持原值。报告另记最终源码哈希及独立读回，不能将最终源码冒充执行源码。


完整长测 `soak-20261012-final-b` 使用同一launch PID312439，连续1854.274秒（30分54秒），只启动一次、零次人工复位，24个实际Goal均终态4。每个终点位置误差0.09–2.93厘米，朝向误差0.0847–0.1055弧度；全部最终停稳及双龄期检查通过。

独立评分为23/24，批次整体failed，`qualified_30_minutes=false`。第18返程的真实接收最大间隔0.344426秒，超过0.300秒；对应最大源间隔0.160秒。该例终点误差2.217厘米、停稳6.20秒，最终接收/源龄期0.02365/0.024秒均合格。保留该记录缺口，不将24个动作成功改写成24个完整验收通过，也不提高门限。

就绪后的完整真值记录还有静止窗口缺口：接收间隔超过0.300秒共7次，最大0.413463秒；源间隔超过0.300秒也有7次，最大0.368秒。逐Goal评分从派发前一帧到最终真值计算，第18间隙跨越派发，因此计为失败；其余缺口多在未派发时。连续运行时长表示进程未重启，不表示完整记录无间隙。完整记录与逐Goal窗口分别保留。

本轮186次进程组采样中，18个进程及895个文件描述符保持一致，RSS峰值1,101,201,408字节。末次RSS为1,097,347,072字节，较首次增加11,649,024字节；这些样本只说明所测窗口的资源范围，不能证明不存在泄漏。清理已完成，11个执行源码SHA均与运行结束后的文件一致。AMCL参数仍只具有上述运行中后验读回，未补造启动回执。

第18接收间隙的具体机制待核实。较小的源间隔不能单独定位订阅调度或文件写入；下一步先记录采集器回调、单次文件写入和生命周期查询耗时，再决定是否调整采集流程。稳定性门禁未通过，不能将本轮作为生产稳定性结论。

## 采样孔洞的最短诊断入口

以下保留原长测b结束时的诊断边界；修复版的实现与新验收另记，不改原失败结果。

pending，owner=root Codex。完整长测b的7个接收孔洞和7个源时间戳孔洞并非一一相同，共8段。sensor_data QoS允许丢帧，header stamp跳变不能单独证明仿真发布端停顿。此轮没有DDS到达或采集循环分段计时，不确定来源、回调排队和文件写入各占多少。

复用 `tools/fishbot_simulation_suite.py` 的 `Recorder.on_truth` 与 `collect`，先增加观测，不调整调度：在truth和 `/clock` 回调记录原始消息时间、DDS MessageInfo时间/序号、回调开始与结束时间；不支持、零值和时钟变化保留unknown，不替换成当前时刻。分别测量 `spin_once`、`update_lifecycle`、`latest-truth.json` 写入及整轮循环耗时。回调内不增加文件写入；用有界缓冲保留孔洞前后窗口及截断计数，退出时一次保存，保留当前完整truth数组与原300毫秒门限。

本机rclpy接口可复用MessageInfo，依据 [rclpy 7.1.12](https://github.com/ros2/rclpy/blob/7.1.12/rclpy/src/rclpy/subscription.cpp)。到达至回调等待增加时，再按分段耗时识别收集端阻塞；源时钟和发布序号同时异常时，才进一步检查来源。仅header跳变仍无法区分发布跳帧和QoS丢帧。已安装的perf/pidstat可补充进程观察，未检出ros2trace入口，不新增追踪框架。以上是接续方案，未采集新指标、未重测长跑，也未改变b判定。

## 修复版的分段观测

`sampling-trace.json` 保存truth与clock的原始MessageInfo、回调起止时间和计时统计。仅原记录器接受的真值触发300毫秒孔洞窗口；未知DDS时间和跨时钟情况保持unknown。回调不写文件，退出时一次flush。当前记录器保留4096个尾部事件、最多32个窗口、每窗最多4096事件，并记录截断数量。

所有spin、生命周期查询、写入与整轮耗时均计数；低于1毫秒的阶段只留统计及 `short_events_omitted`，避免大量空循环挤掉三秒回调上下文。truth和clock回调不筛掉。文件写入失败与ROS清理独立执行，失败记录不阻断所属进程的清理。

诊断 `soak-20261012-trace-a` 在4936帧真值期间重复写入327374次，单次写入最慢117.341毫秒；该轮完整3目标通过，启动前有361毫秒孔洞。此证据确定重复写入及其耗时，不能据此追认原长测b每处孔洞的原因。修复候选 `repair-a` 每4537帧只写4537次，最慢1.556毫秒；177.838秒就绪区间零孔洞，最大接收45.887毫秒、源44毫秒。随后因checkpoint读序复核主动中断，第三Goal取消终态5并清理；整批仍failed，不累计为30分钟通过。

Nav2补丁保留默认2秒查询、原状态变更与bond机制；只在查询异常且ROS未关闭时再查一次状态，错误状态及持续异常仍失败。真实domain103服务故障注入3/3通过：原版迟到查询中止；补丁重查恢复；两次迟到仍中止。配置和激活不重发，实际加载库及参数已核对。底层DDS停顿机制仍未知；完整随机与长测结果另行记录。

## 稳定性修复验收

`random-20261012-repair-a` 原种子1200–1219首试20/20，零冷重启；20个真实Goal各发送一次、接受并返回终态4，独立核对24315帧真值。最大活动接收/源间隔57.615/50毫秒，最大终点误差3.413厘米、朝向0.10088弧度；全部新鲜停稳。5次运动中扫描断流均停车后恢复原Goal。1207的参数、模型和场景与原失败例一致，终点3.263厘米；源与接收最终年龄2/1.458毫秒。

20个实际manager的可执行文件及加载core库SHA均对应本地补丁。400次状态确认均首查询完成；此批没有触发查询重试，重试功能由真实服务故障注入证明。原失败种子、分母和所有日志保留，不将旧19/20改判。

`soak-20261012-repair-b` 同一launch PID680651、一个常驻client，连续1808.296秒（30分8秒），零重启、零复位。25/25实际Goal成功并通过独立物理评分；最大终点误差2.882厘米、朝向0.10406弧度。完整就绪窗口45202帧零孔洞，最大接收82.449毫秒、源56毫秒，原300毫秒与250毫秒门限保持。根Agent独立检查到记录器退出的扩展窗口45203帧同样连续，资格为true；其末边界比父进程结束晚约49毫秒，范围如实区分。

45300个接受真值只写45300次文件，单次最慢8.445毫秒；相比诊断版327374次重复写入明显减少。182个资源样本的18进程/895FD恒定，RSS首次1,086,373,888字节、末次1,091,747,840字节、峰值1,091,776,512字节。这些资源数据不作为长期无泄漏证明。清理后19个所属PID均已不存在。12执行源SHA与代码提交5746210逐blob一致；运行时原revision字段保留f3ba429，不补造新执行来源。AMCL原始与生成YAML启动前SHA、实际加载库和原始物理记录均已核对。

两批在不同ROS域共用主机并行验收，未并行编译；记录器、输出和进程组各自隔离。随机1208、1210、1213在发送前仍有353/369/360毫秒空窗，不在原活动窗口内，作为额外观察保留。长测包含启动的完整记录也有346毫秒空窗，发生在就绪前；不写成从启动起全程连续。诊断窗口有界截断：长测漏留2157个窗口事件，随机合计50512；完整truth未截断。此结果证明本轮就绪后长测和原随机门限通过，不确定全部旧孔洞的底层因果，也不外推生产稳定性。
