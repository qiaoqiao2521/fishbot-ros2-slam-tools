# FishBot 工作台大范围重构

## Goal

将成果入口、地图导航、巡逻、车臂协同、感知与诊断组成同一个可持续操作的机器人工作台。以地图和场景为中心，统一运行环境、编辑对象、任务反馈和恢复入口。范围包含界面、渲染、前端状态、传输适配、后端桥接与任务协调。

## User Intent

2026-10-18 用户明确要求：“我要的是大范围重构，甚至可以动底层……开始做，先 SpecMesh”。用户认可借鉴成熟商业产品，而非局限于现有页面美化。上一轮建议中的“保留所有现有控制器实现”不是本轮限制。

商业产品的使用规模作为研究线索。实际采纳以所选版本代码、可用开源实现、接口契约和本项目验证为依据。已有实现可以替换、拆分或合并；既有功能和验收事实必须有接续位置。

## Scope

1. 重组工作区：地图/场景画布、上下文工具、对象属性、任务时间线、成果与验收。
2. 统一连接上下文与数据契约，覆盖当前 Java/SSE、Python HTTP、ROS 和相机来源。
3. 重构地图编辑域：选择、移动、旋转、规则草稿、路线草稿、撤销重做、版本与应用读回。
4. 重构任务入口：目标、巡逻、协同、语音共享任务呈现和恢复语义，执行适配器仍可按能力不同。
5. 采用可维护的模型/点云加载器，隔离高频数据、解码和视图生命周期。
6. 收敛部署入口：同源 API、明确运行环境、服务身份、远程工具入口与权限边界。
7. 按迁移矩阵接回旧功能，移除已被替代的路径和重复状态实现。

## Product Contract

### R1 工作区围绕当前场景组织

桌面以主画布、对象列表、上下文属性栏和底部任务栏组成工作面。地图与3D场景可切换，位置、航点、规则、选中对象及任务上下文保持一致。手机以画布加底部面板实现同样任务，不能缩小桌面三栏充数。

成果、历史报告与原始诊断按需展开。当前环境和任务常驻；历史快照不产生实时在线或任务完成状态。首次打开、切页、布局恢复都不派发运动。

### R2 编辑是一项可恢复的事务

用户选中航点、墙或区域后，可以查看名称、位置、朝向和冲突原因。工具按对象提供操作。区分草稿、已保存、已发布和导航已应用。规则与路线分别保留版本；旧响应不能覆盖新草稿。

已有缓存、Web Locks/CAS、几何扫掠与足迹行为纳入迁移合同。可以重构实现。保留原目标与吸附结果；直线预检不能替代 Nav2 绕行。返航点在派发时捕获，任务中固定且可见。

### R3 用户知道任务处于哪一层

统一呈现提交、原生接纳、执行、取消、终态、清理和独立评分。状态不支持时明确缺失，不能用 HTTP 200 或界面计时补造。

任务必须关联运行环境、任务 ID 和来源。超时、迟到响应、刷新和断线后，查询原任务；不得自动重放运动。渲染恢复不改变任务账本。用户能在图上定位拒绝对象，并看到具体可执行修正。

### R4 渲染具有独立生命周期

模型注册表记录来源、格式、单位、坐标变换、关节映射和可用能力。复用允许分发的开源模型及加载器。真实点云、路径、相机和历史回放有清晰来源与时间。

高频数据与 React 控件更新分离。渲染队列只保留最新待处理帧；限点数、内存、频率和解码输入。局部加载失败有明确结束状态与重试入口。恢复 Worker 或 WebGL 不重启 ROS 任务。

### R5 接口可以重构，动作归属必须明确

引入明确的运行环境描述和能力发现。统一 API 访问、错误结构、连接代次和只读数据投影。不能把不同 domain 的服务因为 URL 可达就组合成一个环境。

Java 控制站和 Python ROS 桥可以调整职责。默认方向为一个对网页的同源入口、按能力分开的原生执行适配器；任务协调按真实需求合并重复逻辑。新旧路径过渡时只有一个运动提交入口有效，禁止双写。部署配置由服务器管理，不接受浏览器传入任意代理地址。

### R6 停车与人工控制有明确归属

统一控制权、命令有效期和停车反馈。区分“停止请求已发出”“原动作已取消/控制权已撤销”“实际连续静止”。普通连接或渲染故障按其影响暂停/恢复，不扩大成长期人工解锁。过期非零命令不回放，人工停车保持明确且可解释。

当前Java重复stopLatched和仅用于日志的sequence属于待替换边界。新合同需连接既有最终速度守卫；不能只换字段名就宣称端到端时龄或控制权已建立。

## Architecture Workstreams

| 工作流 | 计划变更 | 初始落点 | 必须保住的行为 |
|---|---|---|---|
| 运行上下文 | 环境描述、能力、连接代次、版本和来源统一 | frontend `lib/`、`hooks/`、`store/`；backend 状态接口 | 跨环境数据隔离，过期响应不污染当前环境 |
| 数据面 | 统一读取适配、订阅生命周期、最新帧与限额 | SSE/HTTP clients、相机帧缓冲、渲染模块 | 原时间与序号保留，失检不刷新旧帧 |
| 命令面 | 公共命令视图、语义化错误、原任务恢复 | station API、mission/cooperation/voice 适配 | 只有原生证据才能宣称接纳/终态；未知不重发 |
| 编辑域 | 文档/草稿与运行状态分开，选择与操作事务统一 | `map-zones.ts`、`patrol-mission.ts`、草稿缓存与页面 | 规则版本、完整足迹、撤销不覆盖其他字段 |
| 场景工作面 | 共享画布宿主、对象属性、任务栏、移动面板 | `App.tsx`、map/simulation/cooperation 组件与样式 | 桌面/手机同任务，旧入口可定位新工作区 |
| 后端边界 | 单一网页入口、能力适配、原生动作与实时读回 | Spring Boot服务、mission/cooperation bridge | 原动作唯一归属，评分与执行隔离 |

后端目标拆分为：ROS adapter、业务状态机、只读快照投影、HTTP adapter、证据记录器。优先先迁只读数据，再接公共命令视图，再依次替换mission、cooperation和legacy控制路径。Java可保留为兼容adapter或在完成对等替代后退休，不将Spring Boot设为不可改项。

### 计划采用的组件

- 桌面布局：Dockview React MIT核心。使用现成分栏、标签、调整大小和布局序列化；默认提供任务化预设。手机使用单主视图和底部面板。
- 三维：Three.js官方GLTF/PCD加载器和URDFLoader，业务层只适配TF、单位、模型与关节映射。
- Foxglove：保留外部诊断候选，不依赖需组织账号/商业资格的Embed完成本轮核心交付。
- 版本和许可证核验见findings。P1/P2先做实际依赖与构建兼容检查，未通过则记录缺口并选可维护替代，不能把网页文档当已安装验证。

工作台级provider持有连接、任务与只读投影，面板只消费数据。面板隐藏、拖动、关闭、重开或重复添加不得生成第二个业务owner。按Dockview可见性事件暂停重渲染；地图/3D保持DOM时仍需显式停RAF和视频解码。布局持久化只保存显示配置，不保存动作、凭据或运行日志。

拟新增的抽象只围绕以上已有重复点。不得先搭建通用调度平台、通用插件市场或第二套机器人执行器。

## Visual Direction

- 主体：高可读的浅色操作面，图形对象使用稳定语义色；避免状态提示占满首屏。
- 初始颜色：工作面 `#F5F7FA`、面板 `#FFFFFF`、主文字 `#1D2736`、动作 `#2359D1`、成功 `#237A63`、异常 `#B84332`。后续视觉验收可调整，不能仅靠颜色区分状态。
- 字体：优先本地中文无衬线字体；正文14–16px，属性13–14px，标题22–28px。技术标识只在诊断与详情出现。
- 桌面：紧凑环境条＋画布工具；左侧对象、中央画布、右侧属性；底部任务栏。支持折叠，不默认要求任意拖拽布局。
- 手机：顶部环境和任务；地图保持主要面积；编辑与任务使用可展开底部面板，主要动作保持触达。
- 动效：响应选择、拖拽、保存和状态变化；相机用已完成解码的新帧替换，避免周期性闪白。

```text
环境 / 场景 / 连接                           当前任务 / 停止
对象与图层 | 地图、点云或车臂场景（上下文工具） | 选中对象属性
           |                                  | 冲突与修正
任务进度、原生反馈、取消与恢复                  历史 / 验收
```

这只是布局方向，不是完成的视觉稿。P2需实际桌面和手机截图评审。

## Acceptance

### A. 用户流程

- A01：进入、刷新、切页和恢复布局不提交动作；运行环境常驻且与数据来源一致。
- A02：编辑对象、撤销/重做、规则保存/应用、路线模板与移动操作均有真实验收。
- A03：冲突指出具体对象与位置；编辑后旧诊断不错误标红新对象。
- A04：离线编辑、重连复核、多标签冲突、坏存储与旧回执不会丢草稿或补发动作。
- A05：目标、巡逻、协同与语音能定位原任务；取消、未知、清理与终态均有可操作反馈。
- A06：相机/点云/模型独立失败和恢复；机器人任务不因视图重建而被取消或重发。
- A07：现有成果与报告全部可到达，原失败不改判；场景/视频工具按实际部署配置打开。

### B. 数据与底层

- B01：测试不同domain、连接代次、scene/episode、地图/规则版本、任务UUID及迟到返回的隔离。
- B02：为每个原生adapter列出实际支持的接纳/取消/终态能力；不支持者不得伪造统一语义。
- B03：渲染只读，真值只用于既有允许的仿真反馈或独立评分。视觉检测仍不读取车体真值。
- B04：服务重连、取消竞态和结果查询走真实owner；没有双写、盲重试或由网页判定物理成功。
- B05：沿用日志默认关闭/有界诊断、完整证据预算、缺失即失败的评分合同。
- B06：慢消费者下有界处理并暴露丢弃/缺口；地图按版本更新、遥测保留最新、任务事件按序核对，不能共用无差别丢弃策略。
- B07：人工控制权、取消和停车回执完成端到端验证；旧Java发布成功不得显示为原生接纳。
- B08：任务事件重连核对sequence/gap，并从原任务账本只读恢复。无法补齐时显示历史缺口，不按最新快照补造事件或宣称全量记录。

### C. 可用性与性能

- C01：1440×900与1280×800下，中央画布可视高度至少占视口55%；主动作无需滚动寻找。
- C02：390×844下，画布可视高度至少占视口45%；可完成选点、规则编辑、保存和取消，不发生横向溢出。
- C03：在同机、固定地图/点云输入下记录本地选择到反馈P95、渲染帧率、队列/内存和数据龄期。本地交互反馈目标P95≤100ms；原生接纳、网络响应和连续停稳分别计时，不纳入该UI门槛。指标先测基线再锁定面板，不用加快刷新伪造源新鲜度。
- C04：固定回放连续30分钟检查队列上限、监听器/连接释放与堆增长；报告实际值和未覆盖项，不仅报告截图或构建成功。
- C05：重构后视觉与交互由真实浏览器验证；单测、无头截图和实际ROS面板分别记录。
- C06：Dockview隐藏/恢复/移除/重开、WebGL丢失恢复、坏布局缓存、布局版本升级均有验收；隐藏视图不持续占用高频渲染，任务订阅不因面板重复创建而翻倍。

### D. 实际ROS/MuJoCo面板

使用新的独占domain、API端口与私有输出目录，启动前核对当前占用并记录；不沿用过时端口假设。原保留实例仅只读核验身份。

最小面板包含网页路线保存/规则应用/实际导航及返航、运动取消、断流与未知回执恢复、渲染故障期间任务持续、两轮同世界完整运输与显式重置。接回语音时验证同一入口的预览/确认/取消。每轮使用原UUID、独立物理评分和连续停稳。若修改观测或控制算法，扩大到对应已有专项面板；原视觉11失败单列，不要求用UI重构冒充修复。

## Migration and Rollback

1. 给每项旧功能建立“旧入口→新入口→执行owner→验收”的清单，先接纵向流程。
2. 过渡只允许一条动作路径启用；可比较两份只读投影，不影子派发运动。
3. 新旧接口以明确版本兼容；保留原字段含义，新增能力不能静默改变旧客户端语义。
4. 按阶段独立验收。P0/P1独立提交；P2–P6共享工作面、控制owner和恢复合同，以通过验收的整体版本交付，避免拆出未经验证的中间版本。切换前确认任务终态与清理；未知任务不得靠切换服务接管。
5. 删除旧实现前验证无调用方、行为覆盖和恢复入口。回退时恢复匹配的前后端版本及配置，不回放旧动作。

P1按robot/runtime/能力建立唯一owner与写入路径清单。切换记录服务身份、连接代次和新旧写入开关，并由服务端拒绝已退休代次的命令；采用现有进程独占或必要的代次fencing，不把网页单入口当作服务端无双写证明。回退先确认原动作终态和旧writer退出，再启用匹配版本，核对命令路径与只读回执。无法确认时保留原账本与恢复入口。

## Ownership and Boundaries

根Codex串行维护三文件、PROJECT、DECISIONS与跨仓索引，负责整合和独立验收。子Agent按组件或只读评审分工，不能同时改共享合同。

当前只做虚拟环境。实车、刷写、付费GPU、训练、服务器公网部署和网络变更不在本轮自动执行范围。商业原始包、凭据、地图、运行日志与模型许可不明的素材不进入公开仓库。源代码替换遵循来源许可；行为参考可用自有实现。
