# Findings

- The React console's navigation queue/cancel/clear is explicitly preview-only; telemetry reads /map, /amcl_pose and Nav2 action status but no goal dispatch exists.
- Existing console teleop publishes unstamped Twist to /cmd_vel; it must not be connected to this TwistStamped filtered simulation path. New simulation page offers mission actions only.
- Nav2 waypoint follower and task executor are already configured. Reuse real action feedback and missed-waypoint results rather than building a patrol planner.
- Light simulator has static virtual circles; this task adds a physical actor to MuJoCo, not another visualization-only obstacle.
- Existing MuJoCo GUI startup can stall when a lifecycle configure response is lost. Installed lifecycle service waits can be unbounded; startup gate must have its own deadline and gate RViz on actual state.
- MuJoCo 0.1.1 includes SetFreeJointState for controlled free bodies. Restrict this helper to the named external obstacle and keep robot wheel propulsion untouched.

- Complete browser missions passed three times before actor tuning; one actor return cycle safely froze at its 25-second limit. The underlying async-service gap made movement slower than the requested speed and a moving car invalidated an old side-staging point. Keep the failed trace separate; successful navigation alone is not actor acceptance.
- Actor fix accounts for time between actual write requests, compresses only fully swept-clear A* segments, replans stale side approaches and preserves the 25-second hard limit. Per-step clearance remains checked against the current measured car.
- Actual paused simulation produced ready=false / clock-paused reason, null truth and actor coordinates; the frontend must accept these null coordinates and preserve readiness. Resume returned ready=true. The browser's development hot reload kept one old polling closure; reloading the final page tested the updated parser.
- Startup environment has optional ROS variables, so disable nounset only while sourcing ROS setup. Jazzy lacks launch.actions.LogError/RaiseError; use supported actions and raise RuntimeError on a failed ready child so launch reports failure.
- The desktop MuJoCo vendor renderer reported a GLdispatch segmentation fault during a controlled SIGINT shutdown after successful missions; final web verification uses headless physics. This is an upstream viewer-close limitation, not an active navigation crash.
- Chrome proxy was blocked and the X11 browser fallback found no visible browser window. Actual UI testing proceeded in a separate Codex in-app browser tab, without touching the user's browser credentials or reconnecting its proxy.

- Final corner fix keeps a 4 mm arrival threshold and requires swept clearance to the next actual segment before skipping a corner. Repeated short-cutting from (1.9203,-0.0719) toward the next segment was the return-cycle loop. Regression cases cover both the original 34 mm offset and a 3 mm residual offset.
- Lifecycle readiness queries now remove/cancel expired futures and retry. Callback ownership rejects late replies from an older request; unknown remains not-ready until a fresh real response confirms ACTIVE.
- On 2026-10-05 independent source review found no new blocker; Python 27/27 boundary tests, frontend simulation 8/8 plus typecheck and wrapper syntax checks passed. This is source verification; the saved 120-second telemetry independently confirms the final physical task result.
- Final evidence review confirms three patrol points plus home (four total), succeeded with no missed points, observed duration 90.9379 seconds. Final physical position error is 0.11643 m and speed is approximately 6.06e-11 m/s. The actor returned to (-0.7,-0.7); 33/33 held-blocking lidar frames contain matching actor-surface rays.
- During blocking the robot continued turning while forward translation slowed; no simultaneous low-linear/low-angular complete-stop sample was present. The trace contains no Collision Monitor state event, so it cannot attribute a forced stop to CM or identify a particular Nav2 recovery action. The minimum 8.24 cm net clearance is a discrete geometric estimate only.
- The accepted browser frames show actual obstruction, changed navigation path and continuing patrol, but no terminal screen. The 11-second GIF/MP4 is a captured-frame excerpt; terminal completion is evidenced by task telemetry plus physical truth, not a fabricated video ending.
- Final delivery review also passed the full frontend build, 21 tests and lint on 2026-10-05. A reviewed source allowlist covers src/public and required top-level configuration, including the diagnostics component under src/components/logs; .gitignore uses /logs so this legitimate source is included.
