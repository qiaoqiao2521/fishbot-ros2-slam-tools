# 批量场景、故障演练与停车回放

## 目标

用户确认开始实施纯仿真建议的前三项：批量窄口与路线验收、行驶故障注入、停车原因与真值轨迹报告。复用现有 MuJoCo、passage 控制链、Goal 客户端、守卫事件和 mission bridge。

## 范围

仅隔离仿真；不操作实体、网络、固件或当前网页运行实例。新增合成场景不读取或改写私有住宅地图。保留未核实 release.sh。自主探索与视觉泛化留给后续任务。

## 步骤

- [x] 核对实际运行入口、消息契约与已有报告。
- [x] 参数化合成门口并加入运动触发的扫描故障。
- [x] 复用现有 Goal 执行，收集真值、守卫与碰撞状态。
- [x] 生成批量 JSON、轨迹图、停车原因与失败回放入口。
- [x] 补齐 mission bridge 已接受任务的异常收束与真实碰撞状态显示。
- [x] 执行离线检查和完整仿真，独立复核交付。

## 成功标准

- 固定 seed 可恢复场景参数；每个场景独立进程组，清理只作用于自己启动的进程。
- 窄口与路线成功需要动作结果、真值有序覆盖和最终停稳。
- 断流在实际移动后发生；报告须证明暂停、恢复与继续原 Goal，且无需人工 reset。
- 取消与旧命令案例分别验证终态、真值停稳和无过期位移。
- 报告列通过率、总耗时、停顿次数/时长、触发层与证据限制；不把无数据算通过。
- CM 状态只解释其真实 action/polygon，缺来源标未知；不猜测零速原因。
- 已接受任务遇结果订阅异常时保留收束与取消通道，不提前声明任务终止。
