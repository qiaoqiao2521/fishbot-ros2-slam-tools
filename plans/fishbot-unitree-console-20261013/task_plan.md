# Unitree 借鉴能力接入控制站

## Goal

用户要求检索 Unitree App 逆向原对话，并将对应能力实施到 FishBot 控制站。用户已明确选择网页与手机共用的控制站。

## Scope

- 接收原有未提交的地图、扫描和 Goal 第一轮成果，审查后串行整合。
- 在 `/radar` 增加地图初位姿选择、朝向和显式提交；发布标准 `/initialpose`。
- 接收 `/plan`，在地图上显示真实规划路径，并明确失效状态。
- 为已有 `/simulation` 多航点巡逻提供入口。保留其真实 Goal 所有权、取消与结果反馈。
- 验证桌面和手机页面，再以隔离 MuJoCo / ROS 实例检查实际数据通路。

## Non-goals

不复制 Unitree APK、私有资源、固定加密密钥或 BLE 协议；不实现新的航点调度器。不操作实车、固件、Wi-Fi 或 VPN。保留历史验收记录；不将主题发布成功称为 Nav2 接受或定位成功。

## Plan

1. 通过 TraceMesh 定位原对话，核对本地映射与现有实现。
2. 并行实施后端 `/initialpose`、`/plan` 和前端地图工具。
3. 审阅改动，运行相关测试、类型检查和构建。
4. 后台浏览器检查桌面和手机；隔离环境核对初位姿、路径和巡逻入口。
5. 更新项目入口与采用知识状态，核对提交范围并推送既有远端。

## Success

初位姿请求包含 map frame、位置、yaw、协方差和正确 ROS 时间。缺失模拟时钟不能伪装成功。路径使用真实 `/plan`，空帧、错误坐标系和非法数字会清除旧路径。观察模式不发送动作；用户显式提交才发布。巡逻复用已有任务页。实际检查与未覆盖边界分别记录。

## Current

实施、本轮验收和功能远端交付完成。后端、前端和只读复核并行进行，root 已完成实际运行、文档整合、串行提交和远端回读。具体交付状态见 progress.md。
