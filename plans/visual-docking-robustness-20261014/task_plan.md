# 视觉停靠鲁棒性计划

## Goal

在现有 FishBot 与固定 SO101 共同世界中，规划从理想信标到受扰观测、再到真实视觉观测的停靠验收。保持原生 DockRobot、IK/OMPL 与独立运输评分。

P0已完成。用户明确批准并要求实施完整P1–P3：工位AprilTag定位、50次短停靠与6次完整运输。代码接入与实际面板分别验收，不能用接口存在冒充视觉任务完成。

## Background

研究协调已将此计划派给 FishBot 原对话。Arena 闭环收尾时只记录 pending，未建立三文件。用户本次检查 SpecMesh，root 补齐该漏项。

## Requirements

- 用现有源码确认 StationBeacon、观测时间、坐标与 DockRobot 的实际合同。
- 区分理想信标受扰试验与 RGB 视觉定位，分别评分。
- 保留已有停靠、完整抓放、落稳、回位和运输门槛。
- 基线测量后确定扰动范围与未知阈值，冻结面板与留出条件。
- 记录观测失效、取消、终态未知和清理，不重发未知任务。

## Non-goals

不创建新仿真平台，不迁移 Jazzy，不修改 SO101 依赖，不训练模型，不操作实体或分配云端 GPU。只使用新隔离输出与 ROS domain 验证本轮实现；原107/114实例保持。不把研究报告中的接口存在当作多工位或语义导航已验收。

## 后续实施顺序

P0已完成；P1–P3保持下述协议。对本轮默认链的隔离验收不是完整扰动面板或视觉能力验收。

### P0：冻结传感器与评分合同

区分 ideal、perturbed、vision 三种显式观测模式。保留现有默认行为；来源声明不得冒用 idealized_truth_derived。观测绑定 scene、manifest、episode、工位 ID、源时间、坐标系和唯一所有者。使用 ROS 标准消息与现有诊断；置信度、协方差及失检状态由薄适配提供。

确定失效策略：短暂失检不得重发目标；拒绝旧观测，记录具体原因。只有原动作状态已知且所有权、传感与连续新鲜证据恢复，才考虑继续原目标；否则取消并执行现有 cleanup。终态 unknown 保留车辆保持，不借重启接管。

冻结独立 oracle、SO101 实际依赖、场景生成器、XML、Nav2/BT/碰撞与保护参数。派发前保存源 SHA、面板、预算和唯一 UUID；执行结束交叉读回。私有缓存不存在时明确阻塞该评分，不另写一个更宽松的判据。

### P1：建立无扰动基线

在新输出目录与独占 ROS domain 运行现有 prepare/run。就绪后先验证无扰动停靠，再完成同一自由货物装载与运输。复用已有接受范围内的不同初始位置/朝向；基线覆盖数量、seed 列表和每回合预算须在首次派发前声明。

记录相对观测误差、定位残差、真实停车误差、原生状态、停顿与完整运输评分。旧 K/118 回合只作为历史参考，不冒充新面板的父版本数据。噪声等级从基线残差、几何可行余量和可用标定证据确定；没有相机证据时仅称合成扰动。成功率门槛与未知统计阈值待基线确定，不能事后按候选表现选择。

### P2：受扰信标对照

| 条件 | 注入位置与限制 | 需要回答的问题 |
| --- | --- | --- |
| 无扰动 | 使用原理想信标 | 当前基线能否重复完成完整运输 |
| 位置/偏航噪声 | 相对观测层；模型、工位和评分不变 | 观测误差怎样影响停车与交接 |
| 固定偏差 | 独立于随机噪声声明方向与大小 | 是否持续停错、误报成功或靠 plant 保护掩盖误差 |
| 丢检/突发断流 | 只停止新检测；保留最后一帧原时间 | 短缺失与超过原超时分别怎样处理 |
| 遮挡 | 先做明确标为合成的可见性掩码；RGB 阶段再用真实图像遮挡 | 停靠能否拒绝失效观测并正确结束或恢复 |
| 延迟/乱序/重复 | 保留原时间、序号与回合；覆盖现有时龄边界两侧 | 旧帧或跨回合帧是否污染定位 |
| 错误来源/坐标/工位 | 注入错误身份，不移动世界 | 是否拒绝输入并给出可定位原因 |

父/候选共享同一已冻结面板、初态、seed 与预算。调参面板和留出面板分开；新增成功与旧成功丢失逐案例报告。只在完整任务评分、证据与清理有效时比较增益，不以安全停止算停靠成功。

### P3：RGB 视觉定位与完整任务

车载后向相机与内外参已接入。复用系统OpenCV4.6.0的AprilTag36h11检测与IPPE求解，overview JPEG不作为控制输入。20个静态RGB样本先验收标定、可见性和双解，再冻结质量与协方差门槛；运动面板已执行，成功与未通过分别回源progress。

停靠检测与定位观测必须由实际渲染 RGB 检测产生，不得由车体真值生成。现有独立评分、plant 保护、交接安全条件和机械臂碰撞查询继续使用物理反馈；披露这些依赖，不把它们当 RGB 估计。检测失败不静默退回理想信标。记录每帧 pose、误差、协方差/置信度、可见性、推理时间和采用动作的时间；相机序列与任务账本分开保留。

先验证视觉停靠，再复用完整抓放、落稳、机械臂回位、载物运输与终态静止。保留现有模型与物理门槛。仿真视觉完成也不代表真机或 sim-to-real 迁移完成。

## 评分、取消与停止条件

按三层分别报告：观测质量；原生 DockRobot/NavigateToPose 回执；独立物理任务评分。列出位置/偏航误差、源龄与接收龄、失检/误检/过期拒绝、停顿次数与时长、原生结果和失败类别。样本不足时逐回合列数，不制造统计置信度。

保留原停靠物理确认 0.04m/0.05rad、连续证据、双指接触/抬升、完整货物外廓、放稳与臂回位门槛。当前原生 0.02m 检测阈值与真值确认是不同判据；不得混用。理想停车保护仍独立记录触发次数，不能用保护触发伪造原生或视觉成功。

每种新模式都验证运动取消、传感故障、动作拒绝/终态未知与显式新回合。复用原 UUID 查询和 cleanup，确认原生终态、car_hold、连续静止及 guard 禁用 ACK。记录 scene/episode、clock、sequence、physics_steps、相机来源与采样缺口；慢事件尾部淘汰不能写成没有慢事件。

碰撞、越界、抓空/滑落、未释放/落稳、臂未回位、运输掉货、错误观测污染定位或清理 unknown 时，本回合停止并保留失败。不得放宽完整足迹、接触、时龄或物理门槛取得通过。停止隔离环境前独立确认清理，保留原107/114运行与失败记录。
