# Findings
- 根首页原 hero 最多占约370px；状态重复出现于多块嵌套卡，首屏看不到完整控制。
- `connection.mode=live` 只表明使用 ROS 桥接，不能证明实体小车在线；实车已售。状态文案必须区分连接与数据。
- 四页面原本分开渲染；共享外壳不应让 dashboard 持按 hook 挂到仿真页。
- 当前依赖足够完成改版，无需新设计框架。原相机缓冲和任务收据逻辑保持。
- 知识采用：my-programming-world/Wiki/自动化开发范式与智能体协作.md「按当前任务选择验收依据」。UI 必须检查真实渲染和交互，不能用构建通过冒充美观。

- 持按 hook 等待首个 HTTP 回执后才建循环；旧实现松手或切页无法取消仍在 await 的建循环。现用代次标记拒绝迟到回执建循环，切页有挂起方向时主动发零速。4项异步取消回归和隔离持按浏览器通过；这不证明底层网络传输或物理停车。
- 首轮QA把实际 `cmd-vel` 路径误写成 `command`，验收误失败；核对真实 API 路径后修正检查，保留本机 failure.json，不算实现失败。
- 工作区切换必须回到顶部；新增侧栏后已用实际路由验证并修正 scrollTo。手机使用同4项导航，不依赖不可见桌面按钮。
- bootstrap全局hydrated仍可能混合不同资源的最后报告；本轮source summary同时核对fallback mode，显示最近报告，不新增断流检测或生产新鲜度结论。
