# 地图操作与巡逻

2026-10-13：根据用户指定的 Unitree App 原对话，将地图交互接入 FishBot 控制站。网页和手机使用同一 React 页面。实现复用 ROS 标准消息、现有 rosbridge 和已有巡逻任务。

## 操作

1. 打开 `/radar`。默认观察模式只显示地图和扫描。
2. 选择“导航目标”或“重定位”。
3. 在地图上选择位置。
4. 拖动或再次选点设置朝向，也可输入角度。
5. 核对坐标和朝向，显式提交。

地图留白和边界外点击不生成草稿。触屏支持同样的选点操作。发送中不能修改草稿；已发布或回执未知时，同一草稿不能再次发送。需要重新选点或切换模式才能建立新草稿。系统不自动重试状态变更。

重定位发布只代表消息已送出。页面随后观察定位消息更新，但新消息不证明定位正确；应核对车体位置、朝向与扫描。导航主题发布也不代表 Nav2 接受或到达。

“巡逻”进入已有 `/simulation` 页面，复用多航点、返航、取消和真实 Goal 状态。该页操作隔离 MuJoCo 实例。它与 `/radar` 的 rosbridge 通路分别配置，界面明确标识环境；不能默认两页控制同一台车。

## 数据契约

| 接口或字段 | 行为 |
| --- | --- |
| `POST /api/v1/control/goal` | 请求包含 `x/y/yaw/source`，发布 map frame 的 `/goal_pose`。 |
| `POST /api/v1/control/initial-pose` | 同一请求结构，发布 `/initialpose`，类型为 `PoseWithCovarianceStamped`。 |
| 初位姿协方差 | x/y 为 0.25，yaw 为 `(π/12)²`；yaw 用弧度编码四元数。 |
| `navigation.path` | `ready/frameId/poseCount/points/lastUpdate/statusMessage`；最多返回 2000 点，保留首尾。 |
| `/plan` | 接收真实 `nav_msgs/Path`，只显示 map frame；校验全部原点后采样。 |

空路径、非法数字、错误坐标系、断线和连接代次变化均清除旧路径。新 Goal 或初位姿开始提交时也清除旧路径。路径标为“最近观测到的 /plan”，不依靠固定秒数推断失效，因为规划器可能只在路径变化时发布。

模拟环境必须设置 `STATION_USE_SIM_TIME=true`。此时消息使用实际 `/clock`，接收及推进年龄均不得超过 1 秒；缺失、冻结或来自旧连接的时钟返回 `503 clock_unavailable`。系统不回退到电脑时间。实时时钟模式默认关闭该选项。

无效请求返回 400，控制站人工停车锁返回 409。rosbridge 不可用返回 503；传输错误可能发生在发送途中，前端保留回执未知。`clock_unavailable` 属发送前拒绝。离线模式只修改明确标记的预览，不能提交真实地图动作或声称 Nav2 成功。

## 本轮验收

后端 36 项测试、前端 57 项测试、类型检查、构建及相关 lint 通过。桌面与 390px 触屏浏览器通过观察无动作、草稿无动作、显式重定位、真实路径显示、发布后禁止同草稿重复发送和丢回执保留未知的检查。丢回执用浏览器请求中止夹具验证；该请求没有送到服务端，不能称为机器人已经接受后的失联测试。

隔离 ROS domain 106 中，实际收到两次 `/initialpose`，其源时钟年龄为 30/6 毫秒。直接观察到 AMCL 更新和 `/plan`。一个网页单点目标及两轮各三点的巡逻产生七个真实 `NavigateToPose` 成功终态；两轮 `FollowWaypoints` 均成功。

第一轮巡逻返航物理误差 18.83 厘米，未通过既定 15 厘米门槛。将已有仿真配置的 `xy_goal_tolerance` 从 0.12 收紧为 0.03 后，同样两点加返航的第二轮物理误差为 12.57 厘米，通过门槛。3 厘米是定位估计容差，不能称为实际位置精度。最终独立真值停稳 1.146 秒，29 帧最大接收间隔 45.67 毫秒、时钟年龄 4 毫秒。碰撞配置和模型外廓保留。

本轮使用合成 MuJoCo 场景。未安装手机 APK，未操作已售实车，未新增生产稳定性结论。原失败轮和原始日志保留在本机忽略目录，不提交公开地图或运行记录。
